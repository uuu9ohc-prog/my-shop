## 01. 인트로

- **프로젝트명**: 손뜬 스튜디오
- **한 줄 설명**: 정해진 인형 디자인에 원하는 색·털실·크기를 골라, 정성 들여 뜬 나만의 인형을 주문하는 수제 커스텀 인형 스튜디오의 브랜드 사이트.
  - 쇼핑몰이 아닌 브랜드 사이트이며, 주문 완료 화면까지만 보여 주고 **실제 결제는 없습니다.**
  - 가격·제작 기간은 정하지 않았고, 화면에 [미정]으로 표시됩니다.
  - 실제 운영 브랜드인지, 가상 브랜드인지: ✏️ 직접 채우기 (문서에 명시 없음)
- **브랜드 문구**: "한 땀 한 땀, 소중한 인형을 위하여"
- **배포 링크**: ✏️ 직접 채우기 (문서에는 "GitHub 저장소를 Vercel에 연결해 배포 예정, 주소는 아직 없음")
- **기간**: ✏️ 직접 채우기 (시작일 / 종료일)
- **나의 역할**: 개인 작업
  - 기획: (초안) 사이트 목적·방문자·페이지 구조·요구사항·테스트 케이스 정의
  - 디자인: (초안) Figma 사이트맵·와이어프레임, 레퍼런스 분석, 디자인 기준 정리
  - 퍼블리싱 / 바이브코딩: (초안) AI와 단계별로 구현하고 결과를 검토·수정
  - 역할별 실제 비중: ✏️ 직접 채우기
- **Tech & Tools**
  - 언어·라이브러리: React, Vite, JavaScript(캐러셀 컴포넌트 일부 TypeScript), 기본 CSS, React Router, motion
  - 디자인: Figma(사이트맵·와이어프레임), Claude 디자인 시스템 "손뜬 스튜디오"
  - 배포: GitHub + Vercel (예정)
  - 코드 작성에 쓴 AI 툴 이름: ✏️ 직접 채우기
- **포커스**: (초안) 색을 누르면 인형에 바로 보이는 커스텀 화면이 주문 완료까지 이어지는 흐름을 어떻게 설계하고 검증했는지.

## 02. 기획 의도

- **배경**
  - 문서에 적힌 피하고 싶은 방향: 흔한 공장형 쇼핑몰 느낌(빽빽한 그리드, 할인 배지), 유치한 장난감 느낌, 차갑고 디지털스러운 느낌.
  - 기존 웹사이트를 직접 써 보며 느낀 구체적인 불편이나 아쉬움: ✏️ 직접 채우기 (예: 어떤 사이트에서 무엇이 아쉬웠는지)
  - (초안) 옵션을 목록에서 고르기만 하는 주문 화면에서는 고른 결과가 어떤 모습일지 미리 보기 어렵다.
- **목표**
  - 전달하고 싶은 인상: 따뜻하고 포근한 손맛, 정성이 많이 들어간 수제 스튜디오 느낌.
  - (초안) 방문자가 디자인 → 색 → 털실 → 크기를 차례로 고르며 "내가 직접 인형을 완성해 간다"는 감각을 느끼길 원했다.
- **타깃 사용자 한 줄**: 내 공간에 둘 나만의 소품을 찾는 20~30대 (보조: 특별한 선물을 찾는 사람, PC 우선)
- **배경과 목표의 연결**: (초안) 정해진 상품을 장바구니에 담는 쇼핑몰 대신, 고를 때마다 인형이 바뀌고 털실을 뽑아 뜨는 연출을 거쳐 완성되는 흐름으로 손맛 있는 주문 경험을 만들고자 했다.

## 03. 핵심 가설

- **가설 설정 배경 한 줄**: 문서에서 방문자의 필요는 "색을 누르면 인형에 바로 반영되어 보인다", 가장 중요한 행동은 "커스텀을 끝까지 완성한 뒤 주문하기"로 정했다.
- **IF**: P3 커스텀 화면에서 부위 탭을 고르고 색상 칩을 누르면, 그 부위의 색이 인형 미리보기에 바로 반영된다면
- **THEN**: 20~30대 방문자는 모든 부위의 색·털실·크기를 고른 뒤 완성하기(B3-2)를 눌러 P5 완성 페이지까지 이동한다.
  - (초안) 보조 기준: P5에서 주문하기(B5-1)를 눌러 P7 주문 완료까지 간다.
- **검증 방향**: 07의 TC-08(색 즉시 반영)과 사용 흐름 케이스 TC-23·TC-24(P1 → P7 막힘 없이 진행)를 다른 사람이 직접 해 보게 하고, P5·P7까지 도달하는지 관찰한다.
  - 테스트한 사람과 인원: ✏️ 직접 채우기

  - 판단에 필요한 정보(털실 설명, 크기, 가격, 제작 기간)에는 11~13px 작은 글자를 쓰지 않음.

### 인터랙션 1. 고른 색이 미리보기에 바로 반영 (P3 S3-2·S3-3) — 03 가설의 IF

- **무엇을**
  - 부위 탭(디자인별 3개, 호랑이 4개)을 고르고 색상 칩 10개 중 하나를 누르면, 그 부위의 색만 인형 미리보기에 즉시 바뀝니다.
  - 미리보기 아래에 부위별로 고른 색 목록도 함께 보입니다. 페이지 주소는 바뀌지 않습니다.
- **왜**: 문서에 정한 방문자의 필요가 "색을 누르면 인형에 바로 반영되어 보인다"입니다. (초안) 고르는 즉시 결과가 보여야 끝까지 골라 완성하기로 이어진다고 봤습니다.
- **어떻게**
  - 인형을 코드로 그린 SVG 일러스트(`DollArt.jsx`)로 만들고, 부위별 색 값을 받아 바로 다시 그립니다.
  - 고른 값은 React Context(`OrderContext.jsx`)에 모아 sessionStorage에 저장해, P5·P7 요약과 최종 이미지에 그대로 씁니다.
  - 털실 질감은 P3 미리보기에는 넣지 않고 P5 최종 이미지에만 덮습니다.

### 인터랙션 2. 털실이 쌓이고 뽑히는 로딩 (P0 S0-1 → P4 S4-1)

- **무엇을**
  - P0: 털실 뭉치 6개가 아래부터 하나씩 떨어져 쌓이고, 2.4초 뒤 P1로 자동 이동합니다.
  - P4: 고른 '전체 바탕' 색의 털실 뭉치가 돌며 실이 옆으로 뽑혀 나가고, 2.4초 뒤 P5로 자동 이동합니다. P7 완료 이미지도 같은 연출을 씁니다.
- **왜**: 같은 털실 뭉치 그림·진행 막대·배치를 써서 "모은 털실(P0)을 뽑아 뜬다(P4)"로 이어지게 했습니다. (초안) 완성 버튼을 누른 뒤 바로 결과가 뜨는 대신, 인형을 떠 주는 과정을 보여 줘 수제 스튜디오의 인상을 주려 했습니다.
- **어떻게**
  - 털실 일러스트(`YarnArt.jsx`)와 공통 로딩 화면 컴포넌트(`LoadingScreen.jsx`)로 구현했습니다.
  - 움직임 줄이기 설정이면 연출 없이 자동 이동만 합니다.

### 인터랙션 3. 빠진 항목 알림 (P3 B3-2)

- **무엇을**: 모든 부위 색·털실·크기 중 고르지 않은 것이 있는데 완성하기를 누르면, P4로 이동하지 않고 아래를 보여 줍니다.
  - 버튼 위 알림 문구("아직 고르지 않은 항목이 있어요: …")
  - 빠진 섹션 제목 옆 '골라 주세요'
  - 빠진 부위 탭에 빨간 점
  - 첫 빈 항목으로 부드럽게 스크롤
- **왜**: (초안) 여러 항목을 한 페이지에서 고르다 하나를 놓쳐도 어디를 고르면 되는지 바로 알게 해 완성까지 막히지 않게 하려 했습니다. 흔드는 효과는 쓰지 않기로 정했습니다.
- **어떻게**
  - 빠진 항목 목록을 계산하는 함수(`getMissing`)로 검사합니다.
  - 첫 빈 항목의 섹션으로 `scrollIntoView`를 호출하고, 움직임 줄이기 설정이면 즉시 이동합니다.

**TC-08 — 색 즉시 반영** (연결: R-06, 공통, 상)

- 절차
  1. P3에서 첫 부위 색만 고르고 털실·크기는 고르지 않는다.

  3. 완성하기를 누른다.
- 기대 결과: P4로 이동하지 않는다. 알림 문구, 털실·크기 제목 옆 '골라 주세요', 빠진 부위 탭의 빨간 점이 보이고 첫 빈 항목으로 스크롤된다. 흔들리지 않는다.

**TC-24 — [사용 흐름·모바일] 탭만으로 주문 완료** (연결: R-01·R-03·R-05·R-06·R-07·R-09·R-14, 모바일·태블릿, 상)
